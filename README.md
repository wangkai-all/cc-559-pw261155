# 线路资料断点续传与成套发布演示

本地公开数据站发布同一线路的**线路图（SVG）**与**站点表（CSV）**。传输中途掉线后，
站点可能已经修订附件。本演示用虚构数据完整跑通：

1. 下载器掉线时保留 `.part` 分片与 `.sidecar.json` 侧车（保存**原版本标记**）；
2. 恢复前先比对「原版本标记 vs 站点当前标记」，决定**续传旧分片还是从头取新版本**；
3. 装配器只发布图、表**配得上的一份**：附件齐全、内嵌版本一致且等于站点当前版本、哈希核验通过；
4. 可手工触发断点重试，并演示配套表缺失（站点 410 撤回）时拒绝发布。

仅使用 Node.js 内置模块（`http` / `fs` / `crypto` / `path` 等），无第三方依赖。

## 启动

```bash
node server.js          # 端口取环境变量 PORT，默认 8080
PORT=3000 node server.js
```

服务器绑定 `127.0.0.1`，启动时自动把 `data/` 重置为空目录初始状态，浏览器打开
`http://127.0.0.1:<端口>/` 即可。

## 页面操作

| 按钮 | 含义 |
| --- | --- |
| 开始采集线路资料 | 分块下载图、表，哈希核验后装配发布 |
| 模拟断点后修订 | 下载到第 2 个分块掉线，随后站点发布 v2 修订版 |
| 查看配套附件状态 | 重新计算站点标记、本地分片、完整附件、装配裁决 |
| 断点重试（手工触发） | 恢复前比对版本标记，按决策续传或重取 |
| 断点重试（强制从头取） | 忽略本地分片，手工强制重取 |
| 仅模拟断点（站点不修订） | 配合弱标记演示「标记不可靠」分支 |
| 模拟配套表缺失 / 恢复站点表并补齐 | 410 Gone 异常分支与恢复分支 |
| 强/弱版本标记切换 | 强=含 SHA-256 哈希；弱=仅版本号 |

页面业务结果区 `#evidence` 带 `data-evidence-result`（以及 `data-evidence-operation` /
`data-evidence-verdict` / `data-evidence-published`）属性，每次操作后写入单行证据串，
方便核对操作前后内容；页面同时渲染逐项 before → after 变化表。

## 恢复决策（`src/resumePolicy.js` 纯函数）

| 情形 | 决策原因 | 动作 |
| --- | --- | --- |
| 本地无分片 | `NO_LOCAL_PART` | 从头下载 |
| 侧车标记丢失 | `SIDE_CAR_MISSING` | 从头下载 |
| 站点为弱标记（无哈希） | `CURRENT_MARKER_UNRELIABLE` | 从头下载 |
| 版本号漂移（站点已修订） | `VERSION_REVISED` | 从头下载 |
| 同版本但内容哈希变化 | `CONTENT_HASH_CHANGED` | 从头下载 |
| 分片损坏/前缀哈希不符 | `LOCAL_PART_CORRUPT` | 从头下载 |
| 原版本标记一致、分片有效 | `OK` | 断点续传 |

## 目录结构

```
server.js              HTTP 服务（读 PORT，绑定 127.0.0.1）
src/station.js         模拟数据站：分块下发、修订、撤回、强/弱标记
src/resumePolicy.js    断点恢复决策纯函数
src/downloader.js      分块下载、侧车、恢复前校验、原子转正
src/assembler.js       成套核验与原子发布（只保留一份）
src/demo.js            编排：操作前后快照与逐项变化
public/                页面（index.html / app.js / styles.css）
test/                  node --test 用例（35 个）
data/                  运行时生成：staging/ downloads/ published/
```

## 测试

```bash
node --test
```

覆盖正常路径（成套发布、断点续传、重复发布只留一份、撤回后恢复）与异常路径
（版本漂移、弱标记不可靠、配套表缺失、旧版本件、哈希篡改、410 Gone、HTTP 端到端）。
